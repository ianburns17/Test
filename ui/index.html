Architectural Defense Q&A Oral Defense
1. Short vs Long Polling? +
Short polling sends ordinary, non-blocking GET requests at regular intervals (1s). The server immediately returns the current job representation without holding the HTTP connection open. Long polling holds the request socket open waiting on the server until a state change occurs or timeout expires.
2. Immediate Server Response? +
Immediate responses prevent exhausting server goroutines/threads and reverse proxy timeout buffers. Each GET is a snapshot read from PostgreSQL; holding sockets open defeats the lightweight scalability of short polling.
3. Retrieval Error != Processing Failure? +
Required Decision Rule: Could not retrieve status = observation failure. API returned status failed = processing failure.
A network hiccup or timeout only means the browser failed to read the latest state. The background worker may still be actively rendering or may have already succeeded.
4. Stop Loop at Terminal States? +
completed and failed are mathematically terminal in the state machine (JOB-03). Continuing to poll generates useless network traffic and server CPU load since the job status can never change again.
5. Role of AbortController? +
AbortController immediately cancels active in-flight status fetches when a user submits a different image, resets the console, or closes/navigates away from the page, preventing orphaned async callbacks from updating obsolete DOM state.
